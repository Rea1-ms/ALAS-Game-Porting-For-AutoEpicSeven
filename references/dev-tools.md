# 开发工具分类与新增规则

新增、移动或维护开发脚本时先读取本文件，再核对当前工作树的 `dev_tools/README.md`（开发工具索引）和实际调用方。目录分类按用途决定，不能只因为脚本用于开发就放在工具根目录。

## 目录归属

| 位置 | 保存内容 |
| --- | --- |
| `dev_tools/capture/`（设备截图） | 设备截图、快捷截图及截图隐私处理。 |
| `dev_tools/assets/`（素材工具） | 可复用的切图、框选、素材包装生成与闲置素材暂存。 |
| `dev_tools/assets/<业务>/`（业务素材工具） | 需要长期保留、可重放的业务专用素材制作脚本；优先使用通用工具的参数或配方。 |
| `dev_tools/testing/`（离线测试工具） | 统一测试入口、受控失败检查及正式样本预览。 |
| `dev_tools/exchange_code/`（兑换码工具） | 兑换码资料更新。 |
| 当前工作树的 `.cache/dev_tools/<专题>/`（临时开发目录） | 只为本次任务服务的一次性处理脚本、实验和验证记录，不纳入版本控制。 |

正式测试及精选脱敏样本仍放 `tests/`（正式测试目录），业务实现仍放所属 `tasks/`（任务目录），运行产物使用现有忽略目录。素材配方按切图工具或样本清单保存，不为一组固定坐标重复新增脚本。

## 新增前先确定是否值得保留

1. 搜索已有入口和参数，能够通过现有工具或配方完成时直接复用。
2. 仅本次迁移、采样或验证需要的逻辑保存在临时目录。已完成的历史迁移、首次清单生成及写死历史数量的一次性脚本直接归档到忽略缓存，不为保留历史或已有测试另设正式迁移目录。确需日常重放的工具，说明用途、输入来源、输出位置及覆盖限制，再放入对应分类；业务专用逻辑放业务子目录。
3. `dev_tools/`（开发工具目录）根部只保留分类目录、索引和必要的包文件，不新增独立脚本，不用“杂项”“其他”目录代替归属判断。不为未来需求预建空目录。
4. 新增可复用入口后更新开发工具索引；工具说明放所属分类，技能只维护决策规则和必要的命令契约，不重复维护完整文件清单。

## 移动与验收

- 用户已授权目录整理时，核对源文件、目标冲突及当前工作树范围后使用原文件移动，不删除文件，不用复制后删除代替移动，保留用户其他修改和缓存。
- 同步当前源码中的导入、模拟替换路径、子进程启动模块、文档命令、工作流触发路径和技能引用；同时核对文件层级改变后的仓库定位。不能只移动文件或堆放旧路径转发脚本。
- 一次性脚本退出正式目录时，专属测试源码一并归档，分类清单登记退出原因；正式测试不得导入忽略缓存，也不复制原脚本到正式辅助目录维持依赖。仍用于日常维护的工具和测试保留，逐项核对只有已说明的用例退出。
- 不为改生成包装头部的历史命令手改包装或全量生成；修改生成器的后续输出，并在工具索引注明当前入口。历史测试副本和既有验收结果不反向改写。
- 先比较整理前后的完整用例标识，再通过当前统一入口验证受影响工具。涉及运行器或工作流时运行默认全集和受控失败检查；核对模块启动、从其他目录以绝对路径启动，以及有时限时的子进程入口。
- 验证截图与切图入口时，帮助、已有图片预检和离线模拟即可验证的部分不连接真实设备；截图快捷键和实时画面的实机效果需要单独实际验证后才能宣称通过。
- 修改独立技能源码时，同步当前实际加载的仓库技能副本，保留两边原有差异；只改一份不能宣称规则已经生效。只更新本次涉及的路径和规则，不覆盖整份技能。
