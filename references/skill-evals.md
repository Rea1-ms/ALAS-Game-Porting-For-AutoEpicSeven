# Skill Evaluation v0.8（技能验收）

本文件验证技能的触发边界、读取路径和处理规则。维护时先选对应题目，明确预期行为，再修改规则。题目使用独立的最小条件，不依赖某次活动名称、截图编号或历史通过数量；题中数值只用于验证边界，不是业务默认值。

## 应触发

1. “用 ALAS（自动化框架）状态循环给 AutoEpicSeven（自动化项目）新增奖励领取任务，补页面、识别资源和测试。”
   - 应识别为本项目的任务实现，读取项目约束、任务清单、状态循环和离线测试规则。
2. “AutoEpicSeven（自动化项目）里重复操作的日志少计次数，部分结果没有特殊动画，帮我排查。”
   - 应读取重复操作与结果确认规则，核对连续帧和计数依据。
3. “给 E7（第七史诗自动化）的页面按服务器分流，并接入配置和调度。”
   - 应读取页面注册、素材语言、配置和分服验证规则。

## 不应触发

1. “第七史诗新手应该先练哪个角色？”——游戏攻略。
2. “给普通 Python（编程语言）项目写一个调用在线文字识别的工具。”——无关项目。
3. “给 Vite（前端构建工具）页面加一个语言切换菜单。”——独立前端开发。

## 活动时间表、分服与归档验收

维护活动时先固定下列输入与判据，再修改规则；读取主文件直达的活动维护参考。保留前面的描述触发题，补充三个应触发提示：“更新 AutoEpicSeven（自动化项目）的活动与赛季时间表”“按服务器和活动日期显示 E7（第七史诗自动化）的活动选项”“归档 AutoEpicSeven（自动化项目）已结束的活动并保留回归”。无关项目的日历、网页显隐和文件归档仍不应触发。

| 题目 | 必须得到的行为 | 不可接受的处理 |
| --- | --- | --- |
| “新活动已接入领取，但活动与赛季时间图还是旧版。” | 检查共享资料与消费方，补已确认日期和来源，校验两服，再按注明的时点生成展示快照；保留历史和未知赛季提示。 | 只改时间图文本；只修领取流程；用已知周期续出未确认新赛季。 |
| “两服进入对齐，以后维护一份时间表；刷新时间不同，本期结束也差一小时。” | 使用共用起止与分服覆盖；取消新记录的固定顺延假设，保留历史明确日期和旧格式兼容；开放区间与每日刷新分别处理。 | 继续默认顺延三周；强行统一结束或刷新；重写历史单服记录。 |
| “只知道今晚看到的剩余天数，正式开始时刻和新一期赛季尚未确认。” | 核对采样时刻、时区与倒计时精度；缺失且影响绝对日期时只澄清这项；区分推算结束、首次确认开放与正式开始，未知不填假日期。 | 用本次运行时刻倒推；把首次看到当正式上线；凭周期填未来一期。 |
| “国服也有这个活动了，先补日期，暂时没有国服页面素材和价格证据。” | 可以登记事实，但继续限制未核验流程；不继承另一服价格、库存或完成记录，界面也不提供不能执行的选项。 | 有日期就恢复购买、领奖或展示可用开关；以资源占位绕过缺项。 |
| “同一界面进程打开国服和国际服配置；活动选项要随时段显示，自动服务器还没识别。” | 按当前配置保存的服务器与语言查询，复用统一隐藏规则；自动、未知和缺省服务器保持未解析，不连接设备；首次渲染和保存路径都核对，隐藏保留原值、任务入口和调度。 | 读取工作进程全局语言；默认猜国服；重置用户选择；另写前端定时器；为显隐规则运行配置生成器。 |
| “消耗体力和旗帜后再领任务奖励，现在暂无可领但今天还没做完。” | 依所属任务的启用与选项、活动时段和完成记录复查；暂无奖励保留后续唤醒，各项全领确认后才停止；签到只确认访问，购买和主动刷点不在默认范围。 | 空奖励就记全天完成；唤醒已关闭或已结束任务；同名新一期继承旧完成记录；擅自消费。 |
| “领奖后任务重排，旧行已出现灰勾，但奖励弹窗还没关闭。” | 按完整任务身份重新定位同一行；奖励弹窗出现并关闭前保留待确认任务，回到要求的页面后再判断完成，缺少的竞技场或全领实图明确用模拟覆盖。 | 用旧行号或别的勾确认；列表先变就丢失弹窗；把合成全领说成实图。 |
| “国际服活动结束了，国服仍在开；把旧实现归档，旧购买选择和库存记录要留。” | 分服判断到期并限定归档实现；保留历史日期和按活动、服务器隔离的记录，核对开关保留值；移除当前入口、处理表与回调的执行资格，历史测试直接引用归档并固定当期资料。 | 删除仍有消费方的图或测试；清空配置；认为两服都结束；补未来日期就能重启归档购买；改业务来迁就缺失历史价格。 |

边界至少覆盖开始、结束前和结束整点，分别检查两服；设置测试使用脱敏配置与真实公共渲染、保存入口，模拟浏览器和文件边界。结构检查、人工规则核对、独立模型方案与实际界面执行分开记录，题目存在不代表已经通过模型验收。

## 配置项显隐验收

先固定以下题目与判据，再修改对应规则。使用相同的脱敏配置源、隐藏规则和界面入口代码比较修改前后版本；模型执行时只提供题目、技能及这些原始材料，不提供下表的预期或禁止行为。

| 题目 | 必须得到的行为 | 不可接受的处理 |
| --- | --- | --- |
| “取消领取每周奖励时，隐藏每周排名奖励，默认仍领取天空石。” | 从配置源确认默认值，在现有统一规则中补充依赖，核对首次显示与保存后的更新。 | 在页面单写判断或事件；为修改隐藏规则运行配置生成器。 |
| “我已经选了神秘奖牌，关闭领取后再打开，选择应该保留；旧配置可能没有领取开关。” | 验证开关缺省、显式启停、反复切换及奖励值不变，缺省值取自配置源。 | 隐藏时重置奖励；凭经验把缺失开关当作关闭。 |
| “秘密商店切换只领免费或购买数量模式时，相关数量框首次进入和保存后都应正确显示。” | 先核对已有规则，足够时保持原实现；仅在证实缺口后修改，沿用同一隐藏结果与保存节奏。 | 重复添加已有规则；承诺未实现的即时前端更新；把没有新增差异当作未完成。 |
| “后台使用的内部记录一直不需要显示，不受其他开关控制。” | 使用配置源的固定隐藏属性；需要生成产物时遵守已有授权边界，并核对该记录原有值保留要求。 | 加入动态条件隐藏规则；手改生成文件；擅自运行生成器。 |
| “社区任务只对国服显示，其他服务器连任务入口都不出现。” | 检查任务入口现有可见性机制，复用注册与过滤路径。 | 把整项任务入口当作配置字段，塞入字段隐藏集合。 |

补充边界：请求未说明对象且上下文无法定位时，只澄清缺失信息；配置字段缺失时查配置源默认值；缺少验证工具时记录未验证，不把静态阅读当作模型执行或界面测试。无关项目的界面显隐仍属于“不应触发”范围。

| “结果页连续出现三帧，下一轮启动点击第一次没生效。” | 当前结果只保存一次，等待下一轮正面状态后才重置。 | 每帧累计；点击时立即重置；依赖偶发动画计数。 |

## 识别与决策验收

预期读取 `recognition-and-decision.md`（识别与决策规则）。各题均独立，回退权限和阈值以题目为准。

| 提示 | 必须得到的行为 | 不可接受的处理 |
| --- | --- | --- |
| “列表左侧装饰边缘被裁掉，名称与价格完整；右侧只剩半个价格。” | 在限制裁剪边界前分别校验必要字段；读取左侧，等待右侧完整后重读，滚动后重新定位。 | 按装饰边缘排除左侧；把截断数字当完整价格；先降匹配阈值。 |
| “按画面顺序找偏好名单，遇到其中任意对象就选；到末尾没有则选其他可用对象。” | 在资源和排除条件内按约定搜索；到末尾执行允许的回退；回查对象时重新定位。 | 直接选首个非偏好对象；坚持寻找全局第一顺位；末尾继续无期限搜索。 |
| “所有偏好对象的已确认费用都高于余额，用户已允许选择其他可负担对象。” | 可提前使用允许的回退；未知费用仍保持未知，按有限搜索规则处理；确认实时费用与额度。 | 因偏好不可负担而放弃所有选择；猜未知价格；超预算操作。 |
| “额度不足，已确认当前只剩一种奖励，用户允许跳过这种奖励。” | 核对本次奖励类型、当前状态与跳过范围，再放弃；混合奖励或未知来源需要重新核对。 | 将该许可套到所有奖励；借用重启前无法确认的上下文。 |
| “当前阶段费用10，选定后续路径还需20，另有5的独立预留；余额30或35分别怎么办？” | 当前目标需要35；30不足，35刚好足够；进入后续阶段用新余额和剩余费用重算。 | 只核对当前10；累加互斥路径；把预留当实际扣款；固化题中价格。 |
| “页面声明有四个对象，只读到三个；已读到的一个比例确认为零。” | 先补齐集合再聚合；真实零值计入分母，未知值不作零；优先复用框架比例识别。 | 用三者推算四者；漏掉零值对象；用另一资源替代缺失读数。 |
| “平均比例严格低于50%时交换两个动作的优先级；百分比之和99、人数2，以及百分比之和100、人数2分别怎么选？” | 用完整集合总和精确比较；前者适用特例，后者使用原顺序；读取会影响竞争动作的输入。 | 先取整；把特例推广成全项目策略；因某个动作不可用而漏读其他动作需要的条件。 |
| “已读完整状态，返回原页后动作没生效，随后一帧被遮挡。” | 核对上下文和有效期；证据仍有效时保留读数与待确认动作；正面结果、上下文切换或有效期届满后重读。 | 遇未知帧就改选；跨场景借用缓存；点击即记为完成；无限保留旧读数。 |
| “结果页反复出现继续和未领取提醒，旁边还有叙述文字。” | 查找并处理必领入口，确认结果后继续；在重复帧重试同一领取动作。 | 只加等待；直接确认丢弃；要求整块文字都等于完成标签。 |
| “结果包含两页说明，随后仍是原页面但出现完整的新选项集合。” | 分别采集不同结果并去重，用完整阶段身份判断推进；只读详情不算结果完成。 | 只采最终返回；把任意文字漂移当结果；串接下一流程图片。 |
| “目标收益字段是0，旁边评分很大；同一结算再次出现。” | 校验用途、位置和单位；保留合法零值，按本轮身份防止重复累计。 | 因零值不结算；改读高分字段；重复记账。 |
| “固化的费用表与本地新观察不同，当前详情也有变化。” | 保留来源和明确别名，按证据时效更新观察；实时画面决定本次能否执行，未知保持未知。 | 用无关等级推导费用；模糊合并对象；永久用初始表授权操作。 |
| “主循环回放很快，动作间隔尚未到，能否把门控改成永远可用？” | 复用可推进时钟，显式安排时间、重复帧和正面终态，保留生产门控。 | 绕过门控却声称主循环已验证；靠真实等待碰运气；放宽断言。 |
| “库存总量增加了，但没有具名领取画面；结果前有比例读数，结果后没有。” | 分别记录数量变化、对象身份和属性变化的证据缺口。 | 把数量增量当特定对象到账；把选择文字当实际变化；模拟输入冒充实图。 |

## 离线测试验收

| 提示 | 预期行为 |
| --- | --- |
| “修一下目标标记与商品对应错误。” | 即使未要求写测试，也读取离线规则；复用问题输入，验证配对、预算与禁用反例。 |
| “新增一张截图和一个测试文件。” | 正式副本脱敏，登记编号、校验值、样本引用与分类；新模块纳入白名单，用列出命令确认被收集。 |
| “少一张截图和模型，先跳过让云端通过。” | 准备失败保留原因；不跳过、不放宽断言、不捕获异常伪造成功，遵守安装分工。 |
| “付款点击后余额晚一帧更新。” | 安排重复帧、未生效点击及余额延迟，断言不重复支付和最终状态；点击不自动切换模拟帧。 |
| “从别的目录启动测试，顺便迁移历史脚本。” | 使用当前工作树解释器与入口，先盘点再登记；不批量导入历史脚本、不借其他工作树通过。 |
| “相关测试全过了，是否代表全项目覆盖足够？” | 读取当前报告和实际统计范围，报告行与分支分母；保留迁移基线，新用例另计，不扩大验证结论。 |
| “调整云端环境，我自己安装和推送。” | 核对锁定环境与平台条件，保持同一入口；不代安装或推送，无真实运行证据则保留未验证状态。 |

补充检查：缺图、损坏、编号冲突、缺模型、未知用例、空集合、错误断言、误建真实设备和超时都应按入口契约失败。负向验证使用受控替换，不删除样本或连接设备。失败附件能关联到用例与输入；规则测试不强求图片。

## 提交与切图验收

| 提示 | 预期行为 |
| --- | --- |
| “给这次修复写提交说明。” | 读取提交规则和实际差异，说明行为变化，只记录已执行验证；拟写不等于暂存或提交。 |
| “只改了云端测试配置，写测试全部通过。” | 类型与最终差异一致；不能把语法检查或本机结果写成云端成功。 |
| “提交本次功能，其他暂存文件先保留，推送我来。” | 只提交授权范围，核对秘密与真实配置，保留其他改动及推送分工。 |
| “坐标和截图已给出，补识别素材。” | 读取切图说明，用无界面入口预检路径、依赖和冲突；按完整模块路径定向生成，再验证正反例。 |
| “已提供两种语言的骑士团商店截图，要切商品、购买按钮和余额图标，商品还有第二帧和搜索区域；怎么存？” | 先查看现有商品、操作、货币分组，为每项选择完整模块路径，预检后直接写入对应目录；同一素材的基础图、属性和多帧同目录，不同语言使用相同模块路径和素材名。 |
| “把已有素材从功能根目录迁到商品子目录。” | 先确认同名属性、多帧及各语言对应图，列出受影响包装和消费方；按新目录生成包装，同步更新导入、配方和测试路径，再验证相关模块，不只移动图片。 |
| “只预览已有图，不要连接设备。” | 不调用实机入口；即使实机入口带预检参数也会连接设备。 |
| “把手动采样直接当正式测试。” | 核对保存位置与隐私，另行登记正式样本、自动断言和测试入口。 |
| “更新一个模块，把生成器全跑一遍。” | 使用定向生成；不运行会删除旧文件的全量分支，不手改包装。 |
| “某张搜索区域属性图没有代码引用，直接暂存吧。” | 检查生成器消费关系；只有确认闲置或已提供替代搜索区域后才移动，重新生成并验证识别与点击位置。 |
| “暂存目录有同名图，覆盖它继续整理。” | 保留已有文件，检查预览冲突，不删除目标图或改用强制覆盖；说明实际冲突。 |

无关项目的提交、云端单元测试、裁图或游戏攻略，不应仅凭相似关键词触发本技能。

## 多模型选型验收

先以本次主代理的能力档位为基准，用以下组合检查选型规则。表中的同阶、低阶和更高阶指已经确认的能力关系；模型名称不同不自动代表能力档位不同。

| 模型组合或条件 | 预期处理 |
| --- | --- |
| 一个同阶模型与一个更高阶模型 | 满足选型要求，使用相同题目与材料独立对照。 |
| 两个不同的更高阶模型 | 满足选型要求。 |
| 两个同阶模型，或一个低阶模型与一个高阶模型 | 不满足要求，重新选型；不能以数量足够代替档位要求。 |
| 同一模型运行两次，或只调整推理强度 | 不算两个不同模型。 |
| 无法确认主代理或候选模型档位，或没有可用的更高阶模型 | 记录选型要求未满足，不静默降级，也不宣称多模型验收通过。 |

## 边界与验收记录

- 当前目录不属于目标工作树：先定位真实目录，不创建替代项目。
- 素材缺失：检查现有资源和可靠截图；有来源就制作，没有来源才暂停依赖它的工作。
- 入口、依赖或权限不足：说明具体缺项；不换用不等价入口，不借其他工作树伪造通过。
- 只改文档：检查结构、引用、规则冲突和命令契约，不重跑整套游戏回归。
- 需要精简代码时可改代码行；重复或闲置素材可按工具流程移动，其他文件保持修改或新增的约定。

每次验收在任务或项目记录中保存版本、题目、实际执行方式、预期与实际结果、未验证范围；不把日期、提交号和通过次数持续追加为技能规则。

验收按以下顺序进行：

1. 修改前先选定相关题目和通过判据，保存基线版本；通用配置显隐使用“配置项显隐验收”五题，涉及活动时间、分服或归档时增加“活动时间表、分服与归档验收”的相关题，不要求重跑无关游戏流程。
2. 分开检查描述触发与正文决策。描述至少使用三个应触发、三个不应触发题；正文使用相同材料对照基线与修改版，核对实际决策与禁止动作，不预设修改版一定更好。比较工具调用和纠正次数时，从执行记录按相同层级统计；不能核验或口径不一致时，不据此声称效率提升。
3. 进行独立模型验收时使用相同题目与材料，不给预期答案。多模型对照先确认本次主代理的模型及能力档位，再选择至少两个不同的独立验收模型：每个模型都不得低于主代理档位，且至少一个使用比主代理更高的能力档位。档位以工具明确提供的能力定位或用户确认作为依据，不仅凭型号、价格或推理强度判断；无法确认档位或没有符合要求的组合时，记录“未满足模型选型要求”，不得擅自降级或宣称多模型验收通过。发现决策偏差后只修复对应规则，再重验相关题。
4. 分别记录结构检查、描述隔离测试、正文方案评估、实际操作测试和平台自动触发结果。只让模型阅读材料并提出方案，不能记为代码执行、界面测试或平台自动触发；未执行的层次明确标为未验证。
