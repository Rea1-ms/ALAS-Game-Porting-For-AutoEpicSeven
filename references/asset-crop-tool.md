# 切图工具与用法

新增或调整识别源图时，默认使用当前工作树的 `dev_tools.asset_crop`（切图工具）；`dev_tools.asset_crop_ui.py`（交互界面）是内部实现，不单独启动。命名、目录及属性语义仍以资源规范为准，本文件只说明工具操作和当前限制。

## 1. 选择入口

先切换到当前工作树根目录，使用已有 `.venv/Scripts/python.exe`（虚拟环境解释器）。先查 `python -B -m dev_tools.asset_crop --help`（查看帮助）；以下命令中的解释器应替换为实际环境路径。不要从主检出目录借工具，也不为切图任务自行安装依赖。

| 子命令 | 用途 | 是否连接设备 |
| --- | --- | --- |
| `make`（无界面生成） | 已有截图和明确坐标，或重放切图配方；代理默认使用。 | 否。 |
| `open`（打开图片框选） | 人工在已有截图上选区域，需要桌面窗口和交互终端。 | 否。 |
| `live`（实时预览框选） | 从模拟器持续取帧，冻结后人工框选。 | 是，仅用于已授权的手动实机工作。 |
| `capture`（采样一帧） | 保存整张截图及空裁剪配方，不生成源图或包装。 | 是，仅用于已授权的手动实机工作。 |

`live`（实时预览）和 `capture`（采样一帧）可二选一传 `--config`（配置名，默认值为 `aes`）或 `--serial`（模拟器序列号或端口）。它们带 `--dry-run`（不写文件预检）仍会创建真实设备并取图，不得进入正式离线测试或用来检查“能否离线运行”。

缺少资产时先查已有资源和用户提供的截图：有可靠截图就用本工具制作；没有可靠来源才列出需要补充的画面。不要制造虚假素材、手改包装坐标或捕获缺失资产异常。

## 2. 无界面生成与预检

单区域生成需要：图片、素材语言、完整模块路径、资源名、矩形、采样目录名和采样案例名。`--box`（矩形）格式为左、上、右、下四个整数，按原图坐标计算，右下边界不包含；不是位置加宽高。图片必须为 1280×720，工具不会自动缩放。

最小可执行预览如下。所用样本在当前回归库中；资源名和矩形仅用于验证命令格式，不代表真实识别区域，不能去掉预检参数后直接用于业务：

```powershell
.venv/Scripts/python.exe -B -m dev_tools.asset_crop make --image tests/fixtures/dimensional_exploration/MuMu-20260925-231015-103.png --namespace global_cn --module dimensional_exploration --name SKILL_CROP_PREVIEW --box 400,200,500,260 --suite skill_crop_preview --case help_example --dry-run --json
```

参数含义：`--image`（已有图片）、`--namespace`（素材语言空间）、`--module`（完整资源模块）、`--name`（资源名）、`--suite`（手动采样目录名）、`--case`（手动采样文件名）、`--json`（输出结构化结果）。采样目录名和文件名接受小写字母、数字、下划线及连字符，不是运行器的测试集或完整用例标识。

实际制作时，先换成已核对的截图、语义名称和区域，再执行预检；检查输出路径、所属模块、依赖和冲突无误后，移除 `--dry-run`（不写文件预检）执行保存。需要同步生成包装时加 `--extract`（保存后定向生成）；无界面模式默认不生成包装。`--no-extract`（不生成包装）可显式关闭。

结果中的 `status`（状态）为 `preview`（仅预览）或 `written`（已写入）；同时返回源图路径、采样截图、配方、模块、生成文件和 `conflicts`（冲突列表）。预检有冲突也可能返回成功退出码，必须查看冲突列表，不能把退出码 0 当作已写入或可以覆盖。

覆盖已有输出必须明确本次需要更新哪些文件，再使用 `--replace`（允许覆盖）；它会允许覆盖这一批列出的已有输出，不是只覆盖一个素材。不要因为重跑命令方便就默认加上，也不通过删除旧文件避开冲突。

## 3. 多区域配方与属性

`make --recipe <配方路径>`（从文件重放）用于一张截图生成多份素材。配方含以下字段：

| 字段 | 含义 |
| --- | --- |
| `version`（格式版本） | 当前为 1。 |
| `source`（图片来源） | 相对路径按配方文件所在目录解析；保存的新配方通常引用同目录截图文件名。 |
| `suite`、`case`（采样目录与案例名） | 决定手动采样副本的保存位置。 |
| `items`（裁剪项列表） | 每项含 `name`（资源名）、`namespace`（语言）、`module`（模块）、`box`（矩形）；可选 `kind`（类型，默认基础图）和 `frame`（帧号，默认 1）。 |

多个区域必须来自同一张源图。配方文件模式不会重写传入配方，修改区域应直接更新配方后再预检。也支持 `--recipe-json`（内联配方），但相对来源按当前工作目录解析；复杂内容默认用配方文件，避免终端转义问题。使用配方时名称、模块、采样目录等来自配方，其他同名命令参数不会替它覆盖。

类型可选 `base`（基础图）、`button`（点击区域）、`area`（识别区域）、`search`（搜索区域）、`color`（颜色区域）、`grid`（网格）。`--frame 2`（第二帧）生成第二帧后缀；多帧不在资源语义名中追加下划线编号。

除网格外，属性图必须有同帧基础图；第二帧及以后还要求第一帧存在。依赖可以已在当前工作树，也可以在同一配方批次中提供。搜索区域与网格类型仅支持第一帧。重复输出、越界矩形或缺基础图会报错，不静默补齐。

## 4. 人工框选

已有图片用 `open --image <截图路径>`（打开图片），可提前传入素材语言、模块和采样名称。实时模式先按空格冻结，再框选；已有图片初始就是冻结状态。

| 操作 | 含义 |
| --- | --- |
| 左键拖动 | 追加一个矩形；允许多个区域。 |
| 滚轮、右键拖动 | 缩放、平移；保存的仍是原图坐标。 |
| `Z`、退格或删除键 | 撤销最后一个选区，不删除文件。 |
| `C`（查看颜色） | 打印最后区域的平均颜色。 |
| 回车或 `S`（完成框选） | 结束窗口框选，返回终端填写资源信息；尚未写文件。 |
| `Esc` 或 `Q`（取消） | 取消，不保存。 |

每个选区随后填写名称、类型、帧号、语言和模块，再预览输出并确认写入。已有选区时不能解除冻结；先撤销选区。交互模式未指定是否生成包装时会询问，默认选项为生成。给代理批量操作时使用无界面模式，不发送假定的终端输入操纵窗口。

## 5. 输出、隐私与正式样本

- 源素材写入当前工作树的 `assets/<namespace>/<module>/`（资源目录），尺寸仍为 1280×720：保留选区原始位置，其余区域涂黑，并非输出一张小尺寸裁片。
- 当前工具通过仓库公共目录定位主检出，将整图副本和配方写入其 `test/screenshots/<suite>/`（手动采样目录），文件为案例名加图片或配方扩展名。这是工具现有的手动采样行为，正式用例仍在当前工作树维护；工具尚无切换正式样本输出目录的参数。
- 预检会显示实际绝对路径，执行前核对。手动采样可按工具现有路径保存，但不允许借此向其他工作树写业务代码或正式测试；文件系统权限仍按实际写入位置处理。
- 工具目前只把左下角横向 0–180、纵向 680–720 的账号标识区域涂黑，不等于完整脱敏。正式入库前仍检查昵称等其他信息；已有来源与采样目标相同时不会重写源图，不能据此宣称来源文件已脱敏。
- 正式回归另外复制经检查的整图副本，按当前样本加载器支持的命名登记校验值、服务器、场景和引用用例，并补自动断言与必要的入口登记。生成配方或设置采样名称不会自动完成正式测试迁移。

## 6. 定向生成和完成检查

保存素材后，使用工具的 `--extract`（定向生成），或运行 `python -B -m dev_tools.button_extract --module <完整模块路径> --json`（只生成指定模块）。模块参数按完整路径精确匹配，可重复传入多个；父模块不表示包含所有子目录。执行位置仍为当前工作树根目录。

不要无参数运行全量生成器：当前全量分支会删除旧包装文件后重建，违反本项目禁止删除文件的约定。定向模式只重写选中模块的包装文件，仍需检查差异，不手改 `assets_*.py`（生成包装）。

保存成功只证明文件生成。完成前检查资源名、原图与配方可追溯、输出模块正确、包装可导入，再通过正式离线入口验证真实正反例；多布局按钮还要检查点击坐标和状态推进，不能只用素材匹配自身证明有效。

已知验证范围：本说明依据当前源码、命令帮助及已有样本的无界面预检；人工窗口和实机采样需要在对应任务中另行验证，不包含在离线回归声明中。
