# 活动时间表、分服显示与归档

用于新增或更新活动、维护赛季日期、调整活动选项、处理版本对齐及归档过期玩法。这里保存维护方法；具体活动日期、价格、刷新时刻和当次测试结果留在项目资料与验收计划中。

## 先核对现有入口

先读当前工作树的以下资料与相关实现，确认本轮改变的是日期、支持范围、选项还是实际流程。表中路径是查找起点，仓库结构变化时以当前代码为准。

| 入口 | 核对内容 |
| --- | --- |
| `module/game_info/data.yaml`（共享资料）、同目录维护说明与读取器 | 日期来源、共用与分服字段、刷新规则、历史记录和校验契约 |
| `tasks/activity/calendar.py`（活动适配）、`entry.py`（入口）、`limited_activity.py`（限时活动） | 已支持玩法、服务器与语言限制、任务归属和选项登记 |
| `tasks/activity/scheduling.py`（调度）、`common_activity.py`（共用活动页） | 战斗后复查、完成记录、处理表和页面返回条件 |
| `module/config/config_updater.py`（配置更新器）、`module/webui/app.py`（界面入口） | 当前配置如何传入隐藏规则，普通页、后台页与保存后如何刷新 |
| `tasks/activity/calendar.md`（时间图）、任务说明、`TESTING_PLAN.md`（验收计划） | 展示快照时点、当前限制、已验证和未验证范围 |

资料描述游戏事实，活动适配层决定哪些自动流程已经实现，当前截图决定本次能否操作。新增日期可以只用于查询与展示；不能因此把缺少页面素材或流程核验的服务器加入自动领取、购买或可用选项。

## 日期与分服证据

1. 先核对公告或截图的采样时刻、时区与倒计时精度，在 `source`（来源）中注明。缺少采样时刻且会改变绝对结束日期时澄清这项，其他独立工作继续。首次确认开放只能作为已知启用时刻，不能写成正式开始，也不能用它推导每日刷新。
2. 新一期使用新的 `id`（活动标识），保留历史记录。日期带时区，区间包含开始、不包含结束；结束整点即失效，同类时段在同一服务器不可重叠。
3. 只有两服共用时间已确认时才写 `start / end`（共用开始／结束）；差异用对应分服字段覆盖。只确认单服就只登记该服，不把历史单服记录扩展到另一服。版本对齐不意味着所有活动、赛季编号或端点相同；不再沿用固定顺延假设，旧格式兼容与历史明确日期保留。
4. 活动起止、每日服务器刷新、活动自身刷新分别核对；共用日期不改变各服已有刷新规则。周期长度不能单独证明新一期已开始，不按周期续出未知赛季，不继承未经核验的另一服价格、库存或限购。
5. 更新共享资料后，先用项目资料命令校验并分别查询两服，再生成时间图快照并注明查询时点。当前图按服务器保留尚未结束的已知时段，结束记录折叠保存；不能因一服结束就隐藏另一服。未知赛季单独提示，任务不读取展示快照。

资料命令入口为 `.venv/Scripts/python.exe -B -m module.game_info`（当前工作树的资料查询工具），使用 `validate`（校验）、`current --server CN`（查询国服）、`current --server OVERSEA`（查询国际服）和 `timeline`（生成时间图）；`--at`（指定时刻）用于边界查询。先核对当前帮助与维护说明，不把示例日期复制为正式记录。

## 界面选项与执行支持范围

1. 复用 `ACTIVITY_OPTIONS`（活动选项登记）、`ACTIVITY_TASK_MODES`（任务玩法归属）及活动查询；不要在界面再维护另一份日期或凭日期扩大支持范围。新增玩法同时核对处理表、任务归属和开关登记。
2. 显隐读取当前配置保存的包名与游戏语言，再映射资源语言；同一界面可能同时打开多个服务器配置，不能使用工作进程的全局语言作为依据。自动、未知和缺省服务器保持未解析，不猜服务器、不连接设备；识别并保存服务器后重新打开设置页再查询。
3. 通过统一隐藏集合隐藏尚未开放、已结束或不支持的选项。首次渲染、重新打开与正常保存路径保持一致；沿用已有保存节奏，不另外增加前端事件或定时轮询，不承诺未实现的实时刷新。
4. 隐藏仅改变显示，保留用户原选择、任务入口、调度设置和记录。只有用户明确要求隐藏整项任务时才使用任务入口机制。单改资料或动态隐藏规则不运行配置生成器；确需改配置源与生成产物时沿用已有授权边界。

## 领奖完成与后续调度

先按用户要求区分访问签到、任务领奖、购买和主动积点。访问类以确认进入指定页面完成，不自动领取积存奖励或补签；领奖不顺带刷体力、旗帜或购买货币。只处理每日任务的要求不能扩展到赛季任务或兑换。

任务列表可能在领奖后重排，资格和已领标记绑定完整任务身份、计数与同一行按钮，不能沿用旧行号或其他任务的勾。奖励弹窗实际出现并关闭前保留待确认对象，再确认返回要求的页面；未见过的全领状态不能凭空假定。识别、点击间隔与禁止动作仍按现有状态循环和识别规则验证。

战斗与竞技场结算后只唤醒已启用、选项开启、时段有效且尚未完成的所属活动。暂无可领不等于当天完成；各项奖励有全领证据后才停止复查。访问签到不因战斗重复唤醒，活动自身刷新按自己的区间判断。所属任务控制调度与重试，完成记录继续按活动标识和服务器隔离；换一期不复制旧记录，拆任务也不迁走已有固定额度记录。

## 按服务器归档

1. 先分别查询两服端点，确认要归档的是哪一服、哪一期实现。另一服仍开放时保留该服日期；是否恢复自动操作另按页面、规则与素材证据判断。
2. 沿用任务目录的 `legacy`（历史实现）结构保存旧实现、必要配置与文案快照，核对保存内容；兼容导入按当前消费方保留。移除当前处理表、任务玩法归属与战斗回调的执行资格，单改未来日期不得重新启用归档消费流程。
3. 旧开关固定隐藏时核对 `keepvalue`（保留原值），不改变用户启用、购买选择、领取或库存记录。检查历史实现、测试、工具与素材属性依赖，不删除仍有消费方的文件；源素材另按已有暂存工具规则处理。
4. 历史用例直接引用归档实现，固定当期时间和完整资料快照。旧购买测试缺少历史价格时先查输入时点，不能改当前资料或购买业务来迁就用例。当前路径另外验证不会导入或执行归档玩法。

## 相关验证

- 日期：两服的开始、结束前、结束整点，共用字段与分服覆盖，历史单服隔离和未知赛季不续期。
- 显隐：保存的服务器和语言与全局状态冲突、自动与缺省、首次渲染与保存后切换、隐藏保留原值、无关开关不改变结果。使用脱敏配置与实际公共渲染和保存入口，模拟浏览器及文件边界；这不等于浏览器实测。
- 流程与归档：暂无奖励后仍复查、全领后停止、关闭或到期不唤醒、任务重排与弹窗确认、分服记录与旧实现隔离。保持历史断言，缺少实图的状态明确标记模拟。

正式用例按统一离线入口列出并执行，只运行与本轮改动相关的集；修改验证基础设施时再按现有规范扩大范围。具体结果写项目验收计划，不写成技能永久通过数量；只改本技能文档时检查结构、引用与规则，不重跑游戏回归。
