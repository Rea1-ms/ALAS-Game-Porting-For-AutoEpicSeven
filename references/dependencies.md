# 项目依赖与安装约定

处理 AutoEpicSeven（自动化项目）的安装、依赖分组或锁文件前，先核对当前工作树的 `pyproject.toml`（项目配置）、`uv.lock`（依赖锁文件）、相关差异及 `docs/dependencies.md`（依赖说明）。以当前配置为准，不复制历史环境的包清单。

## 安装与分组

- 用户入口固定为 `uv sync --locked --no-dev`（锁定安装运行依赖）；开发入口固定为 `uv sync --locked`（锁定安装运行和开发依赖）。当前解释器范围为 `~=3.10.0`（限定第三点十系列），同步时由工具准备解释器与虚拟环境。
- 运行包放 `[project].dependencies`（运行依赖）；仅供开发的包放标准 `[dependency-groups].dev`（开发组），不放发布可选依赖，也不用旧式开发依赖配置。默认已包含开发组，不重复设置默认组。
- `--only-dev`（仅开发组）不包含运行依赖，不能用作完整开发安装。`--locked`（锁文件一致性检查）失败时先修复配置与锁文件，不能用 `--frozen`（跳过锁文件时效检查）绕过。
- 核对实际导入再调整工具依赖：`pynput`（键盘监听库）只用于截图终端模式的全局热键，图形窗口不依赖它；`setuptools`（包构建与兼容工具）保留现有离线测试的旧包兼容能力，不因看似未直接使用就删除。

## 维护顺序

1. 新增运行包用 `uv add --no-sync <包名>`（登记运行依赖并更新锁文件，不同步环境）；新增开发包用 `uv add --dev --no-sync <包名>`（登记开发依赖并更新锁文件，不同步环境）。手动修改配置后执行 `uv lock`（更新锁文件，不安装依赖）。不要只临时安装而遗漏项目声明。
2. 检查配置与锁文件差异，不混入无关的运行包升级。两者一并维护，保留根忽略规则中的 `!/uv.lock`（允许跟踪项目锁文件）例外，确认锁文件受版本控制。
3. 执行 `uv lock --check`（配置与锁文件一致性检查）、`uv sync --locked --no-dev --dry-run`（运行安装预演）和 `uv sync --locked --dry-run`（开发安装预演）。失败就修复对应声明或锁文件，再重验两种模式。
4. 按任务需要实际同步环境；用户负责安装时保留该分工。依赖或工作流变化继续按离线规范验收，现有测试锁定清单与云端工作流不随本地分组自动迁移。
5. 修改安装契约时同步根说明、开发工具索引与依赖文档。只改文档或技能时检查命令、引用、路由和副本，不重跑整套游戏回归。

安装预演、实际安装、离线回归和云端运行分别记录，不能相互代替。不要把历史通过数量写成当前环境保证。
