# 离线测试与验收

适用于 AutoEpicSeven（自动化项目）的业务、识别、页面、回放和测试基础设施修改。只讨论方案时不用运行测试；实现修复时按下列步骤验证。规则以当前工作树和用户本次授权为准。

## 1. 先读取当前事实

修改前检查当前工作树的以下文件；不要从主检出目录借业务代码、测试副本或个人截图路径：

| 文件 | 核对内容 |
| --- | --- |
| `TESTING_PLAN.md`（验收计划） | 支持范围、阶段状态、已验证证据与待办。 |
| `dev_tools/run_offline_tests.py`（统一入口） | 参数、白名单测试集、准备检查、设备隔离和报告实现。 |
| `tests/inventory.json`（分类清单） | 来源、业务、类别、设备需求、自动断言、迁移状态及排除原因。 |
| `tests/baseline.json`（迁移基线） | 原用例完整标识、结果、样本、解释器、依赖和模型记录。 |
| `tests/fixtures/dimensional_exploration/manifest.json`（样本清单） | 编号到路径、校验值、服务器、场景和使用用例的映射。 |
| `tests/support/exploration.py`（公共辅助） | 样本读取、配置、模拟设备、帧序列及诊断的实际能力。 |
| `requirements-test-pinned.txt`（测试依赖）与 `.github/workflows/offline-tests.yml`（云端工作流） | 当前版本、系统条件、入口及产物约定。 |

2026-09-26 的迁移基线为 5 个文件、59 项肉鸽测试、62 个截图编号；后来默认集增加了 4 项运行器检查。这是历史记录，不是永远固定的通过数量。新增用例另计，保留原基线；当前数量从列出命令和实际报告读取。

当前未完成事项以计划为准：不能把已编写工作流等同于真实云端通过，不能把现有动作记录等同于全部识别区域和历史动作都已收集。公共辅助目前没有通用受控时钟；需要时补充并验证，不能仅在报告中宣称具备。

旧分支缺少上述入口时，先报告缺项并在本次范围内补齐最小离线验证；不得偷偷切换到另一工作树运行。不要为了满足清单顺带迁移全部历史模块。

## 2. 分类和保存

| 类别 | 默认处理 |
| --- | --- |
| 规则：优先级、预算、资源限制、计数 | 有稳定自动断言后纳入正式集。 |
| 截图识别：页面、文字、标记、按钮 | 使用已登记的脱敏样本，纳入正式集。 |
| 流程回放：连续帧、模拟动作、付款、恢复 | 使用明确帧序列和动作断言，纳入正式集。 |
| 资源基础：资产存在、分服导入、页面注册与路由 | 纳入正式集，分服状态隔离。 |
| 实机调试：真实截图、点击、滑动、运行任务 | 独立手动操作，不进入默认入口。 |
| 其他分支、缺样本或过期接口 | 在分类清单登记原因，本轮不自动导入。 |

- 正式测试写在当前工作树 `tests/`（版本化测试目录），成熟测试和精选脱敏样本随代码保存；临时日志、运行产物、账号配置不入库。
- 原 `test/`（历史本机目录）保持忽略且保留原文件。已迁移测试只在正式目录维护，不反向更新旧测试副本，不向其他工作树写正式用例。切图工具的手动采样可按现有主检出目录保存，具体输出及纳入正式样本的方法见 `asset-crop-tool.md`（切图用法）。
- 同一文件有多类用例时逐项记录；不能只按文件名或是否出现设备相关字符串判断能否离线运行。
- 新文件必须在运行器测试集白名单中登记；分类清单负责记录，运行器不会仅凭清单自动收集。禁止全盘发现、导入历史 `test_*.py`（测试脚本）。

## 3. 新增或修复一个问题

1. 找到最小输入、支持服务器及预期结果。已有用例覆盖就复用；缺少时增加针对问题的用例。修复识别或流程问题，尽可能先证明用例能复现失败，再改业务。
2. 规则用例断言边界和结果；模板或识别用例同时包含正例、反例及位置对应；流程用例断言连续帧、动作顺序、禁止动作、最终状态，不能只有“不抛异常”。
3. 复用公共辅助。测试模块不通过实例化另一个测试类获取工具。新增通用读图、配置、模拟动作或诊断能力放辅助层；不要为了测试报告重构业务状态机。
4. 更新分类清单、样本引用和必要的运行器白名单，用列出命令确认新用例、类别和样本关联正确。清单生成脚本服务于历史迁移，重跑前检查是否会覆盖新增记录；不要把它当作日常自动追加工具。
5. 先运行单个用例，再运行相关测试集。修改肉鸽业务、资产或公共测试辅助后运行完整肉鸽集；修改运行器、锁定依赖或工作流后运行默认全集和受控负向检查。仅文档修改做文档验证即可。
6. 查看报告，按实际结果更新计划的验收记录。只有新增修改、失败或未解决疑点才扩大或重复验证；依赖或环境变更、迁移验收需同环境连续两次结果一致。

首轮必须持续保留的肉鸽场景：未收录徽标与商品对应、预算不足和售出排除；投资、恢复生命与未收录商品的顺序；点击无变化、重复旧帧和付款余额延迟；遮挡时保留已确认商品；重复结算和恢复后不重复记账。国服、国际服中文和英文都检查导入与页面基础；肉鸽识别只声明支持国际服中文。

完整整局、网络异常恢复和其他业务模块迁移属于后续范围，不能从局部回归结果推称已覆盖。

## 4. 样本和回放

- 复制到正式样本库前查看识别区域及无关个人信息。遮盖账号标识等信息只改正式副本；原始来源不修改，保留原尺寸和必要识别内容。
- 肉鸽样本当前为 1280×720。按实际加载器格式登记稳定编号、相对路径、服务器、场景、`sha256`（内容校验值）和 `used_by`（完整用例标识列表）。当前编号对应去掉 `MuMu-`（截图文件前缀）的文件名主干；不要编造无法被加载器读取的命名规则。
- 相同内容副本只保留一份正式映射；编号冲突、缺失、损坏必须报错，不依赖递归搜索的首个结果。不要仅为让检查通过而重算变化图片的校验值，先确认变化来源。
- 用公共读取函数注入首帧；离线测试的“先截图”表示准备模拟帧，不调用真实设备。真实设备构造和连接入口应立即报错，不能以启动模拟器解决离线失败。
- 预先定义连续帧；模拟点击只记录动作，不自动翻到下一帧。显式放入重复帧、操作未生效及等待付款的帧；下一张图片出现不能单独证明操作成功。
- 断言应发生与不应发生的动作、重复动作次数和结束状态；回放用完却未退出应失败。涉及计时器时在辅助层注入可推进的时钟，不依赖真实等待或随机失败概率。
- 服务器及素材语言在业务模块导入前初始化；跨服务器检查在独立子进程运行，避免模块缓存污染。不要把 `global_cn`（国际服中文素材空间）当作文字识别模型语言。

## 5. 统一入口与退出状态

使用当前工作树已有解释器：本机默认 `.venv/Scripts/python.exe`（虚拟环境解释器）；云端使用锁定环境的 `python`（解释器）。不为运行本套测试改用 pytest（另一测试框架）或另建临时环境。用户负责安装时，只检查可用性并报告缺项，不自行安装或升级生产依赖。

在仓库根目录使用以下命令；本机将 `python`（解释器）替换为上述虚拟环境路径：

```text
python -B -m dev_tools.run_offline_tests --list
python -B -m dev_tools.run_offline_tests --suite dimensional_exploration
python -B -m dev_tools.run_offline_tests --case <完整用例标识>
python -B -m dev_tools.run_offline_tests --suite all --coverage --timeout-seconds 300
python -B -m dev_tools.check_offline_negative
```

`--list`（只列出）不执行测试，但仍需足够依赖以导入用例；列出成功不等于模型与样本预检或测试通过。`--case`（单用例）从列出的完整标识复制；`--suite`（测试集）以入口当前白名单为准。不要把示例占位符原样执行。

从其他工作目录启动时，以当前工作树解释器运行该工作树 `dev_tools/run_offline_tests.py`（入口文件）的绝对路径；入口从自身位置确定仓库。不要依赖全局模块搜索路径或主检出目录的代码。

| 退出码 | 含义 |
| --- | --- |
| 0 | 所选测试全部通过且零跳过。 |
| 1 | 断言失败、执行异常或测试超时。 |
| 2 | 参数、依赖、样本、模型、未知用例或空集合等准备条件不满足。 |

原 59 项不能因缺样本或模型而跳过；不能删除断言、放宽阈值或捕获异常伪造通过。新增正式用例也遵守零跳过约定。生产业务对不支持服务器的正常分流，不等于允许测试跳过。

## 6. 报告与失败验证

每次运行创建独立产物目录；默认在被忽略的 `screenshots/offline_test_results/`（测试产物目录）。`--out`（指定输出）只接受新的目录，不覆盖、不自动删除原产物。

执行结果检查 `result.json`（结构化报告）、`output.log`（测试日志）和失败附件：版本与环境、数量耗时、通过/失败/错误/跳过分别统计，用例标识、异常、预期与实际、关联截图及模拟动作可以追溯。规则测试没有截图时只要求必要文字。准备失败可能没有完整报告，超时检查超时记录和已有日志。

发现诊断缺少识别区域、模拟动作或关键状态时，在辅助层补采集并用故意失败验证附件；不要声称当前报告已覆盖全部诊断。新增截图用例同步更新样本引用，否则失败时无法正确附图。

修改入口或报告后，使用受控替换验证缺图、损坏、缺模型、错误断言、未知用例、空集合、误建真实设备和超时的相关契约；不得删除真实样本或连接设备制造失败。现有负向脚本只覆盖其代码声明的检查，额外情形需要补针对验证。负向脚本自身通过表示预期失败被检测到，不表示注入错误的业务用例通过。

## 7. 覆盖率、环境与云端

- 覆盖率只测 `tasks/dimensional_exploration`（肉鸽业务），排除生成的资产包装和第三方依赖；同时报告行、分支的分子和分母，不称为全项目覆盖率。测量应在测试及业务导入前开始。
- 迁移前后使用同份业务代码和相同统计范围比较，覆盖行与分支数不得因整理而下降；有下降先查遗漏用例，不靠减少统计范围获得提升。首版记录真实基线，不设臆测百分比；业务变化后的新结果保留日期、版本和变化说明。
- 生产依赖不顺带升级。测试依赖从已通过环境记录，干净环境安装和实际运行后才能确认可复现；依赖清单存在不是验证证据。
- 本机 Windows（操作系统），云端当前为 Ubuntu 24.04（操作系统）与 Python 3.10.19（解释器版本）。以后变更先核对当前锁定清单和官方可用构建；平台特有依赖使用平台条件，命令符合对应终端。
- 本机与云端使用同一入口、样本和判定；当前云端依次获取代码、安装锁定依赖、预检与负向检查、完整默认集、上传摘要和附件。保持业务、资产、测试、依赖和工作流相关变更触发，纯说明文档不触发，并支持手动执行。
- 当前测试执行超时 5 分钟、云端任务 20 分钟、云端产物保留 14 天；本机不自动清理。失败和超时须明确失败，已有日志和附件仍上传。仅仓库读取权限，不放游戏账号凭据。
- 云端有效性必须有真实成功运行及受控失败的证据；本机通过或工作流语法通过不能替代。推送、安装由用户负责时，完成可本地验证的改动并记录剩余验收，不代做或重复索要授权。

## 8. 完成时怎么说明

先写修复结果，再简短说明运行的范围、通过/失败/跳过数量、相关覆盖范围和未验证项。计划状态仅用“未开始、进行中、已验证”，每个“已验证”都应有实际命令和结果记录。不要把本文件的规范写成所有能力均已实现。
